## What's new in v0.8.0

Two halves. The first is being able to argue with a line instead of watching it go past. The second
is a week of discovering that automatic mode had never really worked — in four separate ways, none
of which any test on the machine this is written on could see.

**If a translation reads badly, ask again.** `Ctrl+Shift+G`, the toolbar, or Settings → Translating.
It ignores the saved answer, which is the whole point, since the saved answer is the one you are
trying to replace. It costs a request and the note beside the button says so.

**If the app misread the English, fix the English.** Correct it in Settings → Translating and
translate that instead. Pressing the button on an empty box fills it with what was actually read, so
you correct a word rather than retyping a sentence — and a corrected line that the app has met
before comes back free.

**Lines you never want translated.** One per row in Settings → Translating. Anything matching is
skipped *before* anything is sent, so it costs nothing at all. This is aimed at the case saving
cannot help with: a button prompt or a HUD label that drifts into the capture region reads slightly
differently every time, so every appearance used to be a fresh request.

**A History tab.** Every line the app has translated, newest first, searchable by the English, the
Arabic or the speaker. It has been recording this since v0.5.0 and nothing could read it. You can
correct the Arabic and save it — which fixes that line everywhere it appears from then on, not just
in the list — translate it again, or add it to the never-translate list.

**A second reader, for text the first one cannot make out.** Off by default, and turning it on is a
real choice rather than a convenience: it sends a *picture* of part of your screen to a provider,
where everything else this app sends is text that was already read on your own machine. When it is
on, a frame where words were plainly there and none of them could be read gets a second opinion from
a model that can look at the image — and that reading is checked against the first one and thrown
away if it disagrees too much. That check matters more than it sounds: this kind of reader fails by
producing a fluent, believable sentence that was never on the screen, which is undetectable to
somebody who cannot check it against the English.

**The app can explain itself now.** Settings → Diagnostics → *Write a self-test*. It writes a file
saying which windows are open, which one it decided is your game and why, where the capture region
landed, what it read there, and one line for every poll of the last two minutes. If something is
wrong, that file is what to send.

### Automatic mode

Four faults, one symptom: "auto translate does not switch to the next sentence".

**It could not tell a finished line from a moving background.** The app decided the text had stopped
changing by comparing two small pictures of the screen and allowing almost no difference between
them. Measured against a real scene, with the sentence completely unchanged: mild foliage moves 3–6
cells of 1536 between one look and the next, moderate motion 13–18, heavy 46–58 — and one more
revealed *word* moves 14–18. So in any game with weather, or an idling character, or a sky, a
finished line could never be *declared* finished. It could only run out of patience, and that
deadline lands mid-animation, so what reached the reader was fragments.

Allowing more difference does not fix it, because a revealed word and a moving leaf cost the same.
So the picture now decides only *when to look*, and the words decide what to translate — by being
read twice and saying the same thing. That single test throws out an unreadable frame (which reads
differently every time), throws out a half-typed line (which grows from the front), and accepts a
finished line whatever is moving behind it.

**Video mode then translated nothing at all**, because "the same thing" was set from a measurement
taken for a different question. Real subtitles read a third of a second apart agree with themselves
79–88% of the time, not 90%. Set from readings off a real screen now.

**Changing mode needed switching auto-watch off and on again.** The new timings only took effect on
the next change, and the line you are looking at while you reach for the button is not a change. It
takes effect at once now, without resetting the clock or the request count your session limits are
measured against.

**It never said what it had decided.** The switch was announced to a status line inside Settings,
which nobody inside a fullscreen game can see. It says so on the overlay now, and the toolbar button
shows the reading — the same dial with the needle over to the patient end or the fast end, so it
stays visibly *automatic* rather than pretending you chose.

### Things that stopped working and now do not

**Picking a capture region, or translating one thing once, used to kill screen capture until you
restarted the app.** Both took their own private grab of the screen and let go of it afterwards,
which on Windows means letting go of the one the app itself was still holding. Nothing failed
loudly — capture just returned nothing from then on and the app went quiet.

**A capture that fails now says which failure it was.** Three unrelated Windows errors used to
arrive as one silent nothing, and the only thing the app could say was to ask whether your game was
in borderless windowed mode — while the diagnostic on the same screen had already confirmed it was.

**The History tab took the whole app down** the first time it was opened with enough rows to scroll.

**An unreadable frame made the app translate the line before it.** Handed something it could not
read, the model reached for one of the previous lines sitting alongside it and returned a fluent,
correct-looking Arabic sentence — so everything on screen was one line behind. That is far worse
than showing nothing, because nothing is obviously nothing. The model is now told those lines are
the past, and given a way to say it cannot read this one; that answer is never shown, never saved
and never carried forward.

**A dialogue box that closed and reopened on the same line showed nothing.** Two guards, each
individually right, suppressed it between them.

**Flipping between modes could run past every session limit the app has.**

**Video mode's poll rate had never once run** — a hidden setting shipped with a value that was
written into every settings file the first time it saved, and it silently overrode the mode.
